# Instructions for AI agents

## Code Quality

Run `make fix` after every code change.

## Formatting

When writing Markdown, do not hard-wrap text at 80, 100, or 120 characters. Write each paragraph on a single line. Readers can use soft wrapping to read it.

## Tests

Do not add tests unless explicitly asked.

## Commits

Do not create commits unless explicitly asked.

Before creating a commit, run `make fix` to ensure the code follows the linter rules.

If all or most of a commit was created with AI, include a `Co-authored-by` trailer.

Avoid the Conventional Commits format. Just describe what changed.

## Documentation

All user-facing documentation is written in Russian.

Keep `AGENTS.md` up-to-date. This file should be in English. Maintain this file when changes to the project structure, tooling, architecture, or development workflow make its guidance outdated.

The parent directory may contain a directory with the same name as this repository and a `.wiki` suffix, e.g. `anime365-sidecar.wiki`. This is the GitHub Wiki repository. Keep it up-to-date too. Do not commit there unless explicitly asked. If you update the wiki repository, remind the developer to push those changes.

Treat [.env.example](./.env.example) and the environment variables in the Docker Compose configuration in [README.md](./README.md) as the minimal set of variables required to run the app. Do not list optional variables or variables with default values there. Document all optional variables in the wiki repository.

## Emby API client

The official Emby OpenAPI 3 snapshot is stored in `api/emby/openapi.json`. Run `make update-emby-openapi` to download the current upstream specification directly into that file. Run `make generate-emby-client` from the repository root after updating the specification or `api/emby/oapi-codegen.yaml`. The Make target runs oapi-codegen through `go run ...@latest`; do not install the generator or add it to go.mod. The `pkg/embyclient` package contains only the generated client and models in `client.gen.go`; do not edit this file manually or add handwritten API wrappers or copied models there. The Emby adapter uses generated response methods and model types directly. Authentication, HTTP timeout, and Emby query escaping are configured in `cmd/sidecar/module/embyclient.go`. Both lint and formatter exclusions use `generated: strict` to exclude files with the standard Go generated-code marker from diagnostics and fixes.

## Media server abstraction

Application services depend on `internal/mediaserver.Server`, which exposes library operations using Anime365 domain types, shared errors, and notification metadata. Keep provider SDK types, provider item IDs, playback details, and public URL construction inside adapters. Persistence and storage-specific errors are adapter internals: the shared contract must not require a manifest or any particular database. `internal/emby.Service` implements this contract; `cmd/sidecar/module/mediaserver.go` selects and configures the implementation. Startup calls `Server.Initialize` before starting workers. To add another provider, implement the contract and extend the composition/configuration layer without adding provider branches to application services. The existing Emby manifest format and environment variables remain unchanged.
