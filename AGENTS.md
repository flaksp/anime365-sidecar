Do not create commits unless explicitly asked.

## Anime365 API client

The official Anime365 snapshot is stored unchanged in `api/anime365/openapi.yaml`. Run `make update-anime365-openapi` to download it from the `.org` mirror, then `make generate-anime365-client`. Generation uses `go run ...@latest` and `api/anime365/overlay.yaml` to fill upstream schema gaps; do not install the generator or add it to go.mod. Keep corrections in the overlay, not in the upstream snapshot or generated code. The generated client and models live in `pkg/anime365client/internal/api/client.gen.go`. `pkg/anime365client` exposes generated model aliases and wraps the four JSON operations while retaining handwritten website operations (login, profile, anime lists, watched state, and subtitles). Series, episode, and translation requests select consumed fields through generated `Fields` parameters in `pkg/anime365client/client.go`; keep these lists in sync with domain conversion code. Request nested episodes and translations as whole fields. Embed does not declare `fields`. JSON and website requests share the configured HTTP client and cookie jar. Preserve optional `isActive` semantics and the existing cookie-based authentication; token-based API login requires a registered app and is not part of this workflow. See `api/anime365/README.md` for the known upstream gaps.

## Emby API client

The official Emby OpenAPI 3 snapshot is stored in `api/emby/openapi.json`. Run `make update-emby-openapi` to download the current upstream specification directly into that file. Run `make generate-emby-client` from the repository root after updating the specification or `api/emby/oapi-codegen.yaml`. The Make target runs oapi-codegen through `go run ...@latest`; do not install the generator or add it to go.mod. The `pkg/embyclient` package contains only the generated client and models in `client.gen.go`; do not edit this file manually or add handwritten API wrappers or copied models there. The Emby adapter uses generated response methods and model types directly. Authentication, HTTP timeout, and Emby query escaping are configured in `cmd/sidecar/module/embyclient.go`. Both lint and formatter exclusions use `generated: strict` to exclude files with the standard Go generated-code marker from diagnostics and fixes.

## Tenrai episode metadata

The official Tenrai OpenAPI snapshot is stored unchanged in `api/tenrai/openapi.json`. Run `make update-tenrai-openapi` to download it and `make generate-tenrai-client` to regenerate the episode-list client in `pkg/tenraiclient`. Keep HTTP setup and rate limiting in `cmd/sidecar/module/tenraiclient.go` and catalog updates in the separate `internal/tenraimetadatarefresher` worker. Initial Anime365 metadata uses `episodeFull` as the episode label. The Tenrai worker processes initialized regular episodes only, matching the MAL ID and original Anime365 episode number from the series response. It applies the supplied title, air date, and filler and recap flags independently of the Anime365 metadata workers. Serialize episode metadata read-modify-write operations within each media server adapter so concurrent passes preserve each other's fields.

## Media server abstraction

Application services depend on `internal/mediaserver.Server`, which exposes library operations using Anime365 domain types, shared errors, and notification metadata. Keep provider SDK types, provider item IDs, playback details, and public URL construction inside adapters. Persistence and storage-specific errors are adapter internals: the shared contract must not require a manifest or any particular database. `internal/emby.Service` and `internal/jellyfin.Service` implement this contract; `cmd/sidecar/module/mediaserver.go` selects and configures the implementation. Startup calls `Server.Initialize` before starting workers. To add another provider, implement the contract and extend the composition/configuration layer without adding provider branches to application services. The existing Emby manifest format and environment variables remain unchanged.

## Jellyfin integration

The official stable Jellyfin OpenAPI snapshot is stored in `api/jellyfin/openapi.json`. Run `make update-jellyfin-openapi` to replace it from `https://api.jellyfin.org/openapi/jellyfin-openapi-stable.json`, then run `make generate-jellyfin-client`. Like the Emby target, generation uses `go run ...@latest`; do not install the generator or add it to go.mod. `pkg/jellyfinclient` contains only generated code. Keep handwritten logic in `internal/jellyfin` and client authentication/timeout in `cmd/sidecar/module/jellyfinclient.go`. The Jellyfin HTTP transport also normalizes JSON Content-Type parameters before generated parsing: profile variants make oapi-codegen compare media types literally, while real Jellyfin responses include `charset=utf-8`. Do not patch generated parsers by hand. Jellyfin uses UUIDs and does not support Emby's Path query filter: match paths against paginated query results, including alternate media sources.

`SIDECAR_MEDIA_SERVER` selects exactly one adapter (`emby` by default, or `jellyfin`). Validate the selected provider's required settings and reject settings for the other provider; construct only the selected client. Existing Emby environment variables remain compatible. Both adapters opt into `internal/libraryfiles` for file management only, supplying adapter-owned storage through its `Store` interface. Each adapter owns its manifest implementation under its own `internal/manifest` package; do not share manifest serialization or add cross-provider compatibility or migration. Preserve Emby's existing `manifest.json` JSON schema. Jellyfin uses `manifest-jellyfin.json`, `jellyfin_item_id` fields, and a required `media_server: jellyfin` ownership marker. Startup must reject another provider's manifest in the same directory, including a renamed foreign manifest. Switching an existing library between providers is unsupported. Document optional settings in the wiki, including the selector and provider-specific public base URLs.

## Season display metadata

Fribb mappings provide a display season number, preferring a positive TVDB season and falling back to a positive TMDB season. Both initial and periodic metadata refreshes call `Server.UpdateSeasonMetadata`. Adapters rename only the main season item to `N сезон` and lock its Name field, preserving other metadata and locks. Both adapters also set the season item's `IndexNumber` and its episodes' `ParentIndexNumber` to the mapped number and identify the item by its `Season 01` path so subsequent refreshes still find it. Both adapters apply episode season numbers in `InitializeTranslationMetadata` and `UpdateTranslationMetadata`, using the MAL ID from their own manifests and skipping specials and trailers; do not scan episodes from `UpdateSeasonMetadata`. When Fribb has no positive season number (including season 0, missing mappings, or an unavailable mapping service), use index 1 for the main season and its regular episodes, and use Anime365 `typeTitle` (`show.Show.TypeLabel`) as the season title. If that type title is empty, preserve the existing title and its locks while still applying index 1. Do not change episode numbering, filesystem paths, or specials (season 0) for display numbering.
