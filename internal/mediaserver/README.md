# Абстракция медиасервера

`Server` — интерфейс между прикладными сервисами сайдкара и конкретным медиасервером. Загрузчики, очистка библиотеки, обновление метаданных и синхронизация просмотренных серий используют операции с идентификаторами Anime365. Типы SDK, идентификаторы элементов медиасервера, проверка воспроизведения и построение ссылок остаются внутри реализации.

Интерфейс реализуют `internal/emby.Service` и `internal/jellyfin.Service`. Функция `module.MediaServer` создаёт только выбранный адаптер и возвращает его как `mediaserver.Server`. Выбор задаёт `SIDECAR_MEDIA_SERVER` (`emby` по умолчанию или `jellyfin`); одновременная настройка обоих серверов запрещена. Перед запуском фоновых обработчиков `startup.InitializeMediaServer` вызывает `Initialize`: адаптер проверяет и загружает собственное состояние, затем определяет путь к библиотеке. Формат манифеста и настройки Emby сохранены.

Для подключения Plex или другого медиасервера нужно реализовать `Server` в отдельном пакете и добавить создание и конфигурацию адаптера в `cmd/sidecar/module/mediaserver.go`. Прикладные сервисы менять не требуется. Способ хранения состояния — внутренняя деталь адаптера: он может использовать манифест, SQLite, другое хранилище или работать без локального хранилища. Интерфейс `Server` не требует манифеста.

Если элемент не найден в медиасервере, методы поиска и обновления метаданных возвращают общую ошибку `ErrItemNotFound`. Проверять её следует через `errors.Is`. Ошибки внутреннего хранилища относятся к реализации адаптера и не входят в общий контракт. `EpisodeMetadataForNotification` содержит готовую ссылку и данные для уведомления без зависимости от SDK медиасервера.

Методы безопасного удаления возвращают `false, nil`, если удаление отложено из-за воспроизведения или срока хранения. Ошибки запросов к медиасерверу должны прерывать удаление.

Оба текущих адаптера используют необязательный помощник `internal/libraryfiles` только для работы с файлами. Хранение состояния реализовано отдельно в `internal/emby/internal/manifest` и `internal/jellyfin/internal/manifest`; каждый адаптер передаёт своё хранилище через `libraryfiles.Store`. Emby сохраняет прежний формат `manifest.json`, Jellyfin использует несовместимый `manifest-jellyfin.json` с полями `jellyfin_item_id` и обязательным маркером `media_server: jellyfin`. Переключение существующей библиотеки между медиасерверами не поддерживается: при обнаружении чужого манифеста запуск прерывается. Совместимости форматов и миграции между адаптерами нет. Всё это детали реализаций, а не требования интерфейса `Server`. Адаптер Jellyfin использует сгенерированный клиент, UUID и постраничные запросы: путь файла сопоставляется локально, поскольку API Jellyfin не поддерживает фильтр `Path`. При объединении версий учитываются пути из `MediaSources`.
